#### The frame equation, measured

The previous next-lever ("authenticate the compiler's local and
compiler-temporary stack map, then move the pending array down four bytes")
is now arithmetic rather than a trace. Compiling the real translation unit
across a grid of declared-scalar counts (0..3 added) and array sizes
(0x1D..0x22) gives, with no exceptions in 24 measurements:

    frame = roundup8(fixed + 4 * scalars + aggregate_bytes)
    aggregate_base = frame - 4 * scalars - aggregate_bytes

where `fixed` is everything below the locals: the outgoing-argument area, the
ten saved registers, and the compiler-temporary block. Reading the two objects
through that equation:

    candidate   8 scalars   6 temps (24 bytes)   fixed 96   T 160   frame 256   pending at 96
    target      9 scalars   5 temps (20 bytes)   fixed 92   T 164   frame 256   pending at 92

The two sides spend the same fourteen four-byte slots and partition them
differently. The target declares one more local and asks the compiler for one
fewer temporary. Both swapped slots are *unused* in the emitted code, which is
why nothing but the array's base address shows it.

That also explains why every earlier attempt failed in the same direction.
Adding a declared local alone moves the array the wrong way (+4, frame 0x108),
because it raises T without lowering fixed. Sixteen such probes ran here: a
ninth scalar in every declaration position, a named effect bound, a named list
count, a named source object, a named update rate, a pending cursor. All land
the array at 100, never 92.

`fixed` responds to exactly two things. First the outgoing-argument area:
cutting func_80036544's call to four arguments drops fixed by 8 and moves the
saved registers down with it, which the target does not do, so the target's
argument area is ours. Second the temporary count, which drops by one only
when a declared pointer carries the object walk:

    cursor = &((Objects0784CObject **)D_800C9494)[objectOffset];
    do { object = *cursor; ... cursor += 1; } while (objectOffset < count);

That is the only spelling found that produces frame 0x100 with the array at
92, and it is exact on the frame. Its loop body then differs by about 200
words, because a declared pointer cursor and the target's index-with-byte-

first copy loop, the two update loops, the effect loop and the pending walk

Next lever: an object-walk spelling that declares a carrier the compiler would
