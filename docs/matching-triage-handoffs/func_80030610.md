#### 2026-09-09: the frame is an equation, and both unknowns are measured

Every frame this function can take satisfies

    frame = 72 + S + L

where 72 is the outgoing-argument area plus the ten saved registers, `L` is
cfe's declared-local block laid top-down from the frame top in declaration
order, and `S` is the reserved register-temporary area between them. The
declared block's *bottom* is what `message` sits on, so `message` is always
`frame - L`, and `done` and the aggregate follow from the declaration order
above it.

- Target: frame `0x98`, `savedCommands` at `0x80`, `done` at `0x7C`,
  `message` at `0x70`. So `L = 40` and `S = 40`, and the forty bytes are
  eight above the aggregate, its own sixteen, `done`'s four, eight more, and
  `message`'s four: declaration order `[8][savedCommands][done][8][message]`.
- Candidate: `L = 24`, `S = 48`, frame `0x90`, `message` at `0x78`.

That reverses this handoff's previous conclusion. The four missing slots are
*not* four more spilled values. The target reserves **two fewer** register
temporaries than the candidate and carries sixteen more bytes of declared
locals. Measured directly, with the fast direct-`cc` loop:

- an eight-byte declaration ahead of the aggregate (or a third `s64` element)
  takes the frame to the exact `0x98` and 87 words to 81, moving the first
  mismatch from `+0x0` to `+0x40`;
- adding the second eight bytes between `done` and `message` puts `message` at
  `0x70` but takes the frame to `0xA0`, because `S` stays 48;
- `S` is 48 in every candidate shape tried, and the target's is 40.

The target writes exactly one temporary slot (`0x4C`) and the candidate one
(`0x48`); every other reserved slot is never touched, which is the
`spilltemps` law in `docs/ido-learnings.md` -- a slot is taken whether or not
the temporary reaches memory, so the count is invisible in the disassembly and
only the frame arithmetic reads it.

So the open question is narrow: find the source shape that creates two fewer
register temporaries. Flat or worse against it in this pass: `nestedCommand`
spelled as an `s8 *` cursor (87 words, frame unchanged); hoisting
`sc->curRSPTask` into a local (-1 word); `>> 1` for the four `/ 2` sites (-13
words); dropping `nextCommand` (-3); using `nextCommand` for the two restore
stores (+1); reordering the two `s64` saves (+1); rewriting the message
`switch` as an if/else chain (-7 words, so the switch is load-bearing); and
swapping the increment order in the 0xB8 scan (87). Do not repeat the
declaration-order sweep -- it moves `L` and never `S`.
