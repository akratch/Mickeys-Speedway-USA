# Pool-rotation lever pass, lane `lane/pool-spike`

Three overlay plateaus whose residual was recorded as "pool rotation" were
re-opened and read with the instrumented uopt CDX colouring profile
(`ido-instrumented/cc`, `CDX_LOG=1`). Six builds were spent. One function is
proved fully reachable by colour alone; one is not a rotation at all; one is a
rotation whose cause sits upstream of colouring. No match was reached, and no
source file in this lane is changed from as-found.

## Reopen gate

All three were `already-integrated/exhausted`. Pins were committed first and
every status re-confirmed with `--base HEAD`, per the `lever-res2` note that
`lane_status.py` reads the authorizations file from its resolved base and
never from the working branch.

## Method

`CDX_LOG=1 CDX_OUT=<file>` on a per-TU compile records one `p1cand`/`p1dec`/
`p1color` or `p2dec`/`p2color` line per allocator decision, carrying the web
number, the save cost, the interference count, the available-colour mask, and
the chosen colour. `CDX_PROC=<ordinal>` scopes it (the profile refuses a
symbol name; `procindex` maps ordinal to decision count). `CDX_FORCE=` then
pins chosen webs and the build is re-measured with `tools/wb_compare.sh`.

Two orders matter and they are **not** the same order:

- **p2**, the caller-saved sweep, visits webs in **ascending web number** and
  gives each the lowest free colour.
- **p1**, the callee-saved sweep, is a repeated **max-save** selection: every
  round re-scans all uncoloured webs and takes the largest save, with
  **ascending web number as the tie-break**.

Read the lane *lengths* before anything else. Equal pool-lane lengths on both
sides is the precondition for calling a residual a rotation; unequal lengths
are a population difference and no colour lever can close them.

## Candidate law: a pool rotation is a visit-order artifact, and which
## source lever moves it depends on which sweep owns the webs

For webs coloured in p2, the assignment is a pure function of web numbering:
save cost is inert. For webs coloured in p1, the assignment is a function of
save cost first and web numbering only within a tie group. So a rotation among
p1 webs that are **tied** on save is reachable by renumbering; a rotation
across a save boundary needs the cost changed instead, which means changing
use counts or loop depth, which changes the instruction stream.

### Evidence that save cost is inert in p2

`overlay43FilterImage`, 9 decisions, all p2, every one `bestcost=0.000000`.
Visit order 0, 2, 6, 9, 12, 16, 60, 73, 84 — strictly ascending. The saves at
those webs are 560.5, 3.7, 23.7, 155.0, 200.0, 1400.0, 120.0, 25.0, 10.0. The
largest save in the procedure is coloured sixth, so the order cannot be
priority. `overlay60ReassignChoiceSlots` repeats it: 10 decisions, all p2, all
`bestcost=0.000000`, ascending web order, two webs declined at save 0.

### Evidence that p1 is max-save with a web-number tie-break

`overlay4UpdateObjectMotion` (proc ordinal 1) is the only one of the three
whose webs reach p1. Its selection order is 146, 98, 0, 132, 6, then 2, 13,
22, 48, 50, at saves 7.0, 4.0, 3.0, 2.0, 1.714, and then **five webs all tied
at 1.5 taken in ascending web number**. The `p1cand` lines make the mechanism
explicit: each round re-lists every uncoloured web with its save and a running
`best=`, and the winner is the maximum.

### Evidence that the target's assignment is reachable — the force oracle

`overlay4UpdateObjectMotion` was 8 words, `allocation-mismatch`, 0 opcode and
0 schedule differences, frame equal, temp lanes identical 54/54, fp lanes
identical, and pool lanes equal at 42 slots each. The residual was three web
substitutions. Forcing the switch-selector web 13 to v1 alone took it from
**8 words to 5**, closing all three sites of the first substitution. Forcing
web 13 to v1 together with the tied pair web 48 to a0 and web 50 to v1 took it
to **words=0** — every instruction word identical, with only the 11
relocation-symbol placeholders the extracted target carries for its own calls
still outstanding. That is a complete reachability proof: the whole residual
was three colours, all three are legal (uopt accepted every force and added no
instruction), and webs 48 and 50 are a tied pair whose order is decided by web
number alone.

### Where the other two actually sit

`overlay43FilterImage` is **not a rotation**. Its pool lane is 18 slots on the
target and 15 on the candidate: the target colours three values we leave in
the temp ring, and its temp lane is correspondingly 18 against our 21. Forcing
the four-web rotation to the target's colours made the first five pool slots
exact and improved 33 words to 26, but raised opcode mismatches from 8 to 10.
The shard's "the residual is one cyclic pool rotation" is falsified; the
population deficit of three is the real blocker and colour cannot reach it.

`overlay60ReassignChoiceSlots` is a genuine rotation by the length test — both
pool lanes are 22 slots — and the whole 35-word residual reduces to three
substitutions, essentially a v0/v1 transposition. But the cause is upstream of
colouring: the target materialises the `available` base address twice, once
for the initialisation walker and once, after that loop, for the persistent
base, and emits no register-to-register copy. We materialise it once and copy,
because the source reuses one `choice` variable across all three loops, giving
one web with a live range spanning the function. Forcing colours cannot delete
a copy, and the two webs interfere (9 each), so they cannot be coalesced.

The relocation caution on this function is an extraction artifact, not a
defect: the target object names only two of its four address materialisations
(both `D_D0`) and leaves the other two unrelocated, while our four aliases are
all named. Reading the target's own addends confirms it forms two lui/addiu
pairs per pass exactly as our four-alias spelling does, so the comment in the
source about preserving two address-materialization lifetimes is correct and
the single-array theory is disproved.

## Source spellings tried, and why they failed

| Function | Spelling | Result |
|---|---|---|
| `overlay60ReassignChoiceSlots` | give the initialisation walker its own `u8 *` local instead of reusing `choice` through a cast | **regression**: 35 -> 37 words, frame -0x20 -> -0x28. The extra declared local took a stack home, the same cost `func_80005868` paid in `lever-res2` |
| `overlay4UpdateObjectMotion` | drop the `else`-branch store to `delta` and pass the call result directly, to renumber the tied pair | **byte-identical** (`bff9732353f3`). cfe had already coalesced that store; webs 48 and 50 kept their numbers |

The second is the same failure mode `lever-res2` recorded on `func_800056A4`:
an edit chosen from a numbering model without first checking that the store
the model depends on survives cfe. The `p1color` lines confirm it directly —
one upstream web number shifted (146 became 145) while 13, 22, 48 and 50 did
not move at all. A renumbering lever must therefore be validated against a
**second CDX capture**, not against the source diff.

## What `diagnose`'s `lever` block needs to name this class

A `pool-rotation` lever would have to do four things in order, and today's
block does none of them:

1. **Gate on lane length.** Fire only when the target and candidate pool lanes
   are the same length. `overlay43FilterImage` is the counter-example the gate
   exists for: it is currently described as a rotation and it is a population
   difference of three. The block already prints both lanes and does not
   compare their lengths, the same blind spot `lever-res2` found in
   `stack-home`.
2. **Name the owning sweep.** A rotation among callee-saved-sweep webs and one
   among caller-saved-sweep webs take different levers. The block cannot know
   which without a capture, so `capture: CDX_LOG=1` belongs in the block
   whenever the residual is register-only and the lanes are equal length.
3. **Name the web and the direction, from the tie group.** With a capture it
   can say what this pass had to derive by hand: "webs 48 and 50 are tied at
   save 1.5 and ordered by web number; the target's order is 50 before 48;
   move 50's first occurrence earlier." Without a tie it should say so, and
   route to cost instead of numbering — that is a different and much more
   expensive edit, and the block should rank it below.
4. **Report the force result as reachability, not as a fix.** `words=0` under
   `CDX_FORCE` is the strongest verdict the workbench can currently produce
   for a register residual and it is not surfaced anywhere. It separates "the
   target assignment is legal and one source lever away" from "the target
   assignment is illegal in our web graph", which is exactly the
   `reachability=` field's job.

One more thing the block should refuse to do: name a renumbering edit without
also asking for the confirming second capture. Both source spellings tried in
this lane were plausible from the numbering model and neither moved a web
number; a capture would have cost nothing and saved both builds.
